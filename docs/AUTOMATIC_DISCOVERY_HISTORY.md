# Automatic opportunity-discovery history

The existing Upstox registry and Spring candle ingestion path now support bounded background backfill, independent of portfolio holdings and browser activity. Compose enables the scheduler, but no collection occurs without explicit market data usage rights, entitlement confirmation and the existing operator UPSTOX_ACCESS_TOKEN. The user vault is not borrowed for shared research. No extra account or bank integration is needed.

Each five-minute fixed-delay pass claims up to two active mapped cash equities per exchange. It only requests completed previous sessions from the configured exchange calendar, prioritizes unattempted instruments and persists attempts across restarts. Missing history gets six months; existing sufficiently long history gets an incremental range. Failed requests wait six hours; successful ones wait a day. Adjusted series are excluded from raw backfill and conflicting writes cannot overwrite existing adjusted or other-source candles. Existing holding and manual research workflows remain available.

The scheduled research overview now scans up to 60 registry instruments per exchange, while manual daily screening retains its existing 20-instrument default. These are bounded daily-history observations, not full-market rankings, live signals or investment recommendations. No automatic external AI usage, order execution or fabricated fundamental data is introduced.

V19 adds an attempt ledger and mapping index; it does not delete records. Check authorized provider rights before activating and ensure market-session coverage. Verify real API behavior, data completeness and local resource use separately from mocked CI. A full market universe, liquidity selection, corporate-action-adjusted history, strategy-specific rankings and automatic AI evidence enrichment remain separate work.

The current scheduler uses a 12-month window, a 200-observation maintenance threshold, and 12-hour success / six-hour failure cooldowns. Known interior gaps now also qualify for repair, even with a current latest observation. Use only stored regular sessions with valid time bounds, excluding weekends, recorded holidays and special sessions; restrict to dates after or on the first recorded observation and within recorded listing bounds. Request from the earliest known missing date when earlier than the normal incremental start. Adjusted series remain excluded from raw backfill. Unknown calendar dates are not inferred and positive writes do not certify coverage. Existing request limits and authorization are unchanged.

## Automatic exchange-calendar bootstrap (local acceptance follow-up)
The empty local market_sessions table prevented every equity discovery attempt. The new opt-in scheduler uses existing authorized operator settings and Upstox's documented date-specific https://upstox.com/developer/api-documentation/get-market-timings/ and https://upstox.com/developer/api-documentation/get-market-holidays/ endpoints. Compose enables ATLAS_EXCHANGE_CALENDAR_SYNC_ENABLED by default; rights, entitlement and token must still be present. Four dates per two-minute pass, newest first, today through 370 prior dates, two bounded requests per date. Persisted claims/cooldowns prevent immediate retry after interruption; shared operator provider cooldown remains authoritative. No weekday-only fabrication: exact-date valid standard 09:15–15:30 IST weekday timings classify regular; other timings classify special, explicit consistent closures classify closed; absent or conflicting venue evidence stays unknown. Existing session rows and manually recorded holidays are retained, no automatic overwrite/reclassification or completeness guarantee. This is a bootstrap/repair of missing rows, not a correction feed for already populated dates. V30 adds only an attempt ledger. Data-health summary adds aggregate calendar coverage and attempt states. No new API routes, private holdings, order actions, or new token. Actual historical range support, date-specific response shape, provider permissions and real data coverage remain to be verified on operator device. The prior 403 fix is merged, not proof of authenticated access.

## Local acceptance: current-session maintenance
A local 27 November diagnostic found 296 of 330 sampled daily histories failed the exact completed-session gate. The maintenance scheduler now separates overdue existing histories (at least 25 stored daily observations) from universe expansion and other repairs. Each two-minute fixed-delay pass allows up to eight overdue histories and two expansion/repair requests per exchange, sequentially with at least a one-second gap before each request in Spring. Existing exact instrument mapping, adjustment exclusions, six/twelve-hour retry ledger, calendar, permissions and shared provider cooldown remain in force. This is not a throughput guarantee: provider latency, missing current bars, cooldowns and quality gates can reduce effective coverage. No qualification threshold or source label changed.
