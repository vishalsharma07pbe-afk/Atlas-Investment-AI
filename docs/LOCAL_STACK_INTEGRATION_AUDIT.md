# Local stack integration audit

This audit fixes two issues identified during source inspection: browser origin checks can reject legitimate state-changing cookie-authenticated requests when the development proxy rewrites the Host header or the production proxy drops an explicit port; and the JWT revocation ledger previously kept revoked sessions for only 15 minutes even when signed sessions lasted days. The development and production proxies now preserve the original Host. New tokens include unique session identifiers, and logout retains the revocation until the verified signed expiry. Existing revoked tokens already purged by previous releases cannot be reconstructed.

The new GitHub CI job builds the actual development Compose stack using disposable credentials, empty test database and external data collection disabled. It exercises HTTP through the frontend proxy: registration/login, session cookies, two isolated owners, holding writes, automatic portfolio review/thesis/diversification, the Spring-to-Python opportunity route, Python-to-Spring registry reads via the automatic scheduler, and logout/revocation. It also checks rejection of anonymous portfolio access and unauthenticated internal Python access. No actual broker credentials, market provider requests or personal data are used. The test's synthetic holdings are destroyed with the disposable volumes; never run it on a personal instance.

The stack smoke tests empty-data behavior, not real-market availability, actual browser rendering, load, or production image acceptance. The production proxy change is not exercised by the development-stack smoke; a separate production runtime check is required. A successful CI run, local live-provider acceptance and visual/accessibility review are still required before claiming readiness.
