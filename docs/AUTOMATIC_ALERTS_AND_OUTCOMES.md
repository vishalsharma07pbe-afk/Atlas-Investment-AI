# Automatic alerts and watch outcomes

The existing portfolio review scheduler now creates a daily owner-scoped in-app digest when a fresh, revision-matching review contains attention findings. It reuses user_notification_history and its dedupe index, with at most one digest per owner per IST date. No email, Telegram or external notification service is activated. The existing bell now combines public feed metadata with an authenticated unread-count endpoint and presents personal notifications with explicit server-side read state. No private alert data enters the public feed.

The automatic research scheduler records the original technical watch publication once per instrument/horizon/observation date. Subsequent evidence cannot overwrite that record. Fixed evaluation horizons are 14, 60 and 180 calendar days after publication for swing, short and long technical watches. At most five mature records per pass request existing local historical data, with daily retry cooldowns. Evaluation uses the first completed close strictly after publication and the first completed close at or after maturity, within seven-day windows. It rejects inconsistent identity, duplicate dates, large gaps, raw prices, manual prices and mixed sources. Unavailable evidence stays unavailable. Observed adjusted close-to-close change is not a trade return or verified strategy accuracy. Existing historical outcome tools remain available.

History is persisted on the existing research SQLite volume. The horizon page provides an optional history disclosure. No new external data or AI request, trade execution, PostgreSQL migration or private-data export. Public watch publication history is not a push notification; opportunity alerts, advanced event delivery, strategy benchmarking and full live acceptance are outstanding. CI tests cover publication immutability, evidence gates, user isolation and read-state behavior.
